## B02: native SQLite connection and transaction ownership

Those V1 tests were inspected, not executed.

The actual V2 dependency is Effect **4.0.6**. Reuse its `SqlClient.makeSqliteAcquirers` for scoped leases, statement borrowing and failed-COMMIT cleanup. Suppress automatic scheduler yields only during scoped acquisition to protect this dependency's permit-to-finalizer handoff; contended waits remain interruptible and transaction callbacks retain normal scheduling. Bun export and Bun/Node extension loading use the native cancellation-safe borrower. Drizzle delegates to native `withTransaction`, preserving configured BEGIN behavior through `BeginTransaction` and the injected workerd transaction path. This removes duplicated transaction/finalizer code rather than transplanting V1's scheduler internals. Savepoints retain explicit release.

Before implementation, the 12-test regression suite had **10 pass / 2 fail**: a Drizzle waiter remained uncancellable while a holder owned the connection, and a deferred-constraint SQL commit left an uncommitted row visible on the connection. Both pass after the adaptation. The original scheduler sweeps used `Effect.void`, which the current generator consumes without counting scheduler operations. Their green result on release V2 and the first B02 version did not establish cancellation safety.

Review pass 1 found that the new scoped acquirer also required operation-local scopes for Bun export and Bun/Node extension loading. New regressions reproduced all three blocked subsequent queries before that correction (12 pass / 3 fail).

Review pass 2 found that scoped acquisition in Effect 4.0.6 can automatically yield after taking the semaphore permit but before installing its release finalizer. Corrected sweeps use counted `Effect.sync` operations and include export/extension acquisition. Before the second correction, **13 pass / 6 fail** reproduced leaks for reservation, export and extension at both budgets: padding 19/17/16 at 32, and 2035/2033/2032 at 2048. The scoped-acquisition scheduling guard and one-shot borrower remove all six failures. This is a concrete dependency handoff reproduction, not evidence that it caused the historical server hang.

## B03: snapshot full-diff input safety

Commit: final review passed; prepared for local commit, with the exact SHA to be recorded in the next ledger update. Native `Git.tree.diff` now obtains changed blob identities, byte sizes and numstat counts before spawning full-patch work. It omits a file from patch generation when either side exceeds **2 MiB** or additions plus deletions exceed **20,000**, unconditionally, including with diagnostics disabled. Equality is allowed. Skipped files retain identity, status and counts, with `patch: ""` matching the frozen V1 guard. Blob metadata is batched without loading file content into JavaScript; submodule commit objects are not queried. Git still computes numstat, so this does not claim to eliminate all large-file scanning or diff-count computation.

The existing aggregate 10,000,000-byte output budget remains in place for eligible files. Its regression now uses six individually eligible 2 MiB files instead of one file that the new input guard must skip. Patch path selection remains literal, case-sensitive and command-line bounded, and separates file/directory replacements so selecting a small parent path cannot recursively reintroduce an oversized descendant. Descendant-only exclusions preserve eligible gitlink parents. Snapshot capture and restore still retain the underlying tracked file data.

This is a deliberately partial F022 batch. No diagnostic writer, JSONL sampler, recovery instrumentation, public skipped-reason field or UI indicator was added. An empty patch with nonzero counts is not proof of an unchanged file.
