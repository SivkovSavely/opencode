# Directory-specific Web project appearance

The opened directory, not the repository ID, owns its Web display name, icon and avatar color. The server stores the revisioned `{ revision, entries }` snapshot in `storage/global/project-appearance.json` under the same data directory as the synchronized project list. Keys use the project list's path normalization. Closing a project changes list membership only; it does not delete appearance. Server connections have separate client snapshots. No session, project or worktree table migration is needed.

The authenticated, Web-only `GET` and `PATCH /global/project-appearance` return the snapshot. A patch is `{ directory, appearance: { name?, icon?, color? } }`; omission leaves a field alone, and an absent stored field inherits the old directory cache or repository metadata. `null` explicitly clears a field: a cleared name displays the folder name, and a cleared icon does not fall back to the shared or detected image. Automatic colors are display defaults, not repository writes. `server.project-appearance.updated` invalidates the snapshot; clients refresh on reconnect and ignore older snapshot revisions. The project list and repository API contracts are unchanged. Older servers without the endpoint still show legacy metadata but do not accept directory appearance edits.

## V2 cutover (upstream v2.2.5, `9bbb8ce18c80f099e0e448775f59d965ead40a21`)

- Keep the server data key, directory key rules, fields (including explicit nulls) and revision semantics. Port the authenticated Web route and invalidation to the V2 HTTP server and event transport. Preserve the fork's existing opened-list ordering/membership separately. Do not backfill appearance from all repository rows or rewrite project IDs. `packages/core/src/project.ts` and `packages/core/src/project/sql.ts` still resolve and store repository-level projects; `packages/schema/src/project.ts` distinguishes repository `canonical` from the current `directory`.
- In `packages/app/src/settings/workspaces/project-model.ts`, keep repository settings through `sdk.api.project.update`, as served by `packages/server/src/handlers/project.ts`. A Web editor for a specific opened entry should instead update appearance using that entry's exact directory; the startup command remains a repository setting. `packages/app/src/settings/workspaces/queries.ts` lists repository metadata, which remains fallback data.
- Integrate the directory snapshot alongside, not into, repository bootstrap (`packages/app/src/runtime/server/global-sync/bootstrap.ts`). Apply it to opened entries and their session presentation in `packages/app/src/shell/layout/project-icons.tsx`, `project-icon.tsx` and `project-avatar-state.ts`. Resolve an exact opened directory for display before falling back to a worktree or repository, without changing grouping, session lookup or routes. Re-run the same multi-directory and persistence regressions against V2.
